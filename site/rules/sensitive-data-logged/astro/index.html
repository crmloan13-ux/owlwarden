Fix sensitive data written to a log in Astro

A password, token, cookie, or similar value is passed to a log sink. Centralised logs are widely readable inside an organisation and often retained for months — a credential that lands there is a credential that has left the application's control.

medium likely Astro CWE-532 · OWASP A09:2021

The vulnerable pattern in Astro

MEDIUM likely Sensitive data written to a log A09:2021 src/pages/api/users.ts:15:18 13 │ 14 │ // sensitive-data-logged: the password reaches the process log. 15 │ console.info({ password: body.password }) │ ~~~~~~~~~~~~~~~~~~~~~~~ sensitive value written to a log 16 │ 17 │ // sensitive-data-logged: an access token, logged the same way.

This is a real finding from the Astro fixture in the owlwarden test suite, in /api/users. Logs are copied into aggregators, retained for months, and readable by anyone with access to the logging system. A credential that reaches a log has left the application's trust boundary.

The corrected handler

Log that the attempt happened, not the credential.

console.info({ event: 'login_attempt', userId })
// never: console.info({ password: body.password })

If you are not using Astro

Log a redacted shape — an id, a boolean, a length — never the secret itself.
