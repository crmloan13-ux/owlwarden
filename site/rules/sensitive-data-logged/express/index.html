Fix sensitive data written to a log in Express

A password, token, cookie, or similar value is passed to a log sink. Centralised logs are widely readable inside an organisation and often retained for months - a credential that lands there is a credential that has left the application's control.

medium likely Express CWE-532 / OWASP A09:2021

The vulnerable pattern in Express

MEDIUM likely Sensitive data written to a log A09:2021 src/app.ts:16:18 14 │ app.post('/login', async (req, res) => { 15 │ // sensitive-data-logged: the password reaches the process log. 16 │ console.info({ password: req.body.password }) │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~ sensitive value written to a log 17 │ 18 │ // sensitive-data-logged: an access token, logged the same way.

This finding comes from the Express fixture in the owlwarden test suite. Logs are copied into aggregators, retained for months, and readable by anyone with access to the logging system. A credential that reaches a log has left the application's trust boundary.

The corrected handler

Log that the attempt happened, not the credential.

console.info({ event: 'login_attempt', userId })
// never: console.info({ password: req.body.password })

If you are not using Express

Log a redacted shape - an id, a boolean, a length - never the secret itself.
