Fix sQL query built by string interpolation in Fastify

A SQL string is assembled with a template literal or concatenation and passed to a database driver. Any value interpolated into it is executed as SQL, so a request parameter can read, modify, or destroy data the query was never meant to touch. Use the driver's parameter binding instead; every driver has it.

high likely Fastify CWE-89 · OWASP A03:2021

The vulnerable pattern in Fastify

HIGH likely SQL query built by string interpolation A03:2021 src/server.ts:21:5 19 │ // sql-injection: concatenated rather than bound. 20 │ const [rows] = await db.execute( 21 │ 'SELECT id, title FROM articles WHERE title LIKE "%' + term + '%"', │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ query text is built at runtime 22 │ )

This is a real finding from the Fastify fixture in the owlwarden test suite. A value taken from the request is interpolated into SQL, so the caller controls part of the statement. That is enough to read other users' rows, bypass a WHERE clause, or drop a table.

The corrected handler

Bind the value; keep the SQL text constant.

await fastify.pg.query('SELECT * FROM users WHERE id = $1', [request.params.id])

If you are not using Fastify

Pass the values as query parameters instead of interpolating them. Every driver supports it, and the binding is not optional formatting — it is what stops the value being parsed as SQL.
