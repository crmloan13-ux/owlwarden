Fix sQL query built by string interpolation in TanStack Start

A SQL string is assembled with a template literal or concatenation and passed to a database driver. Any value interpolated into it is executed as SQL, so a request parameter can read, modify, or destroy data the query was never meant to touch. Use the driver's parameter binding instead; every driver has it.

high likely TanStack Start CWE-89 / OWASP A03:2021

The vulnerable pattern in TanStack Start

HIGH likely SQL query built by string interpolation A03:2021 app/routes/api/session.ts:18:5 16 │ // sql-injection: the email comes straight from the body into the query text. 17 │ const rows = await pool.query( 18 │ `SELECT id, role FROM users WHERE email = '${body.email}'`, │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ query text is built at runtime 19 │ )

This finding comes from the TanStack Start fixture in the owlwarden test suite. A value taken from the request is interpolated into SQL, so the caller controls part of the statement. That is enough to read other users' rows, bypass a WHERE clause, or drop a table.

The corrected handler

Bind the value as a parameter in the server function.

const rows = await pool.query('SELECT id, role FROM users WHERE email = $1', [body.email])

If you are not using TanStack Start

Pass the values as query parameters instead of interpolating them. Every driver supports it, and the binding is not optional formatting - it is what stops the value being parsed as SQL.
