Fix server fetches a URL the caller controls in NestJS

An outbound HTTP request is made to a URL that came from the caller. The server can reach hosts the caller cannot - cloud metadata endpoints, internal admin services, databases bound to localhost - so this turns the server into a proxy into its own network. Validate the destination against an allowlist before fetching it.

high likely NestJS CWE-918 / OWASP A10:2021

The vulnerable pattern in NestJS

HIGH likely Server fetches a URL the caller controls A10:2021 src/users/users.controller.ts:80:28 78 │ async importRemote(@Body() body: { sourceUrl?: string }) { 79 │ // ssrf 80 │ const upstream = await fetch(body.sourceUrl as string) │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ destination chosen by the caller 81 │ return upstream.json() 82 │ }

This finding comes from the NestJS fixture in the owlwarden test suite. The destination of this request comes from the caller, so they choose which host the server connects to. That includes hosts they cannot reach themselves: the cloud metadata endpoint that hands out IAM credentials, internal services that skip authentication because they are 'not exposed', and anything bound to localhost.

The corrected handler

Validate in the service, not the controller, so every caller of it is covered.

const target = assertAllowedUrl(dto.url)
return firstValueFrom(this.http.get(target.toString(), { maxRedirects: 0 }))

If you are not using NestJS

Check the destination against an allowlist of hosts before fetching it. Blocklists do not work here: DNS rebinding, redirects, and IPv6-mapped addresses all defeat them.
