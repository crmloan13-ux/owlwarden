Fix cross-origin policy accepts any origin in Fastify

The CORS configuration accepts requests from any origin. Combined with credentials this lets any site a logged-in user visits make authenticated calls to the API and read the responses. Without credentials it may be intentional for a public API — the finding says which case it found.

medium likely Fastify CWE-942 · OWASP A05:2021

The vulnerable pattern in Fastify

MEDIUM likely Cross-origin policy accepts any origin A05:2021 src/server.ts:29:3 27 │ 28 │ // cors-permissive: hand-rolled wildcard + credentials. 29 │ reply.header('Access-Control-Allow-Origin', '*') │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ accepts requests from any origin 30 │ reply.header('Access-Control-Allow-Credentials', 'true')

This is a real finding from the Fastify fixture in the owlwarden test suite. Any origin may call this API and read the response. That is a deliberate choice for a public endpoint and a mistake for anything behind a session — nothing in the source says which this is, so it is reported for you to decide.

The corrected handler

Register @fastify/cors with an explicit origin list.

await app.register(cors, {
  origin: ['https://app.example.com'],
  credentials: true,
})

If you are not using Fastify

Replace the wildcard with the origins that actually need access, and only send credentials to those.
