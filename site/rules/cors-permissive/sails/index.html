Fix cross-origin policy accepts any origin in Sails.js

The CORS configuration accepts requests from any origin. Combined with credentials this lets any site a logged-in user visits make authenticated calls to the API and read the responses. Without credentials it may be intentional for a public API - the finding says which case it found.

medium likely Sails.js CWE-942 / OWASP A05:2021

The vulnerable pattern in Sails.js

MEDIUM likely Cross-origin policy accepts any origin A05:2021 api/controllers/AuthController.js:25:5 23 │ 24 │ // cors-permissive: hand-rolled wildcard + credentials (detected reliably). 25 │ res.setHeader('Access-Control-Allow-Origin', '*') │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ accepts requests from any origin 26 │ res.setHeader('Access-Control-Allow-Credentials', 'true')

This finding comes from the Sails.js fixture in the owlwarden test suite, in /auth. Any origin may call this API and read the response. That is a deliberate choice for a public endpoint and a mistake for anything behind a session - nothing in the source says which this is, so it is reported for you to decide.

The corrected handler

Give sails.config.security.cors an explicit origin list.

// config/security.js
module.exports.security = {
  cors: {
    allRoutes: true,
    allowOrigins: ['https://app.example.com'],
    allowCredentials: true,
  },
}

If you are not using Sails.js

Replace the wildcard with the origins that actually need access, and only send credentials to those.
