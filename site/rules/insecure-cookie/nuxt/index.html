Fix cookie set without its protective attributes in Nuxt

A cookie is written without `httpOnly`, `secure`, or `sameSite`. Missing `httpOnly` turns any cross-site scripting bug into session theft; missing `secure` sends the cookie over plain HTTP; missing `sameSite` attaches it to cross-site requests. A cookie holding no sensitive value may not need all three, which is why the finding names the ones it did not find rather than assuming the worst.

medium likely Nuxt CWE-614 · OWASP A05:2021

The vulnerable pattern in Nuxt

MEDIUM possible Cookie set without its protective attributes A05:2021 server/api/session.post.ts:11:3 9 │ // insecure-cookie: h3's setCookie is a bare helper, not a method on a 10 │ // response object, and it is called here with no attributes at all. 11 │ setCookie(event, 'session', token) │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ cookie written without httpOnly/secure/sameSite 12 │ 13 │ return { ok: true }

This is a real finding from the Nuxt fixture in the owlwarden test suite, in POST /api/session. This cookie is missing protections: httpOnly keeps the cookie out of reach of JavaScript, so a cross-site scripting bug cannot read the session; secure stops the cookie being sent over plain HTTP; sameSite stops the browser attaching the cookie to cross-site requests.

The corrected handler

Pass the attributes to setCookie.

setCookie(event, 'session', token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'lax',
})

If you are not using Nuxt

Set httpOnly, secure, and sameSite when writing a cookie that carries anything the user would not want read or replayed.
