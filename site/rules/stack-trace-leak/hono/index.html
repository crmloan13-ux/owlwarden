Fix stack trace leaked in error response in Hono

Returning an error's `.stack` to the client exposes absolute file paths, dependency versions, and internal call structure. Attackers use it to map the application and to fingerprint vulnerable dependency versions. Log the stack server-side and return a generic message.

high likely Hono CWE-209 · OWASP A05:2021

The vulnerable pattern in Hono

HIGH likely Stack trace leaked in error response A05:2021 src/app.ts:50:28 48 │ } catch (err) { 49 │ // stack-trace-leak: the client learns the file layout and dependency versions. 50 │ return c.json({ error: (err as Error).stack }, 500) │ ~~~~~~~~~~~~~~~~~~~~ leaks internal stack trace to the client 51 │ } 52 │ })

This is a real finding from the Hono fixture in the owlwarden test suite. Stack traces expose absolute file paths, dependency versions, and internal call structure — enough to fingerprint the stack and locate other weaknesses.

The corrected handler

Log server-side and send a generic body.

console.error(err)
return c.json({ error: 'Internal Server Error' }, 500)

If you are not using Hono

Log the error server-side and return a generic message to the client.
